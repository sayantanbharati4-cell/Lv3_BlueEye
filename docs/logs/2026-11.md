# 2026-11

## 2026-11-02 — More aggressive bot policy

### Context
The robots policy already blocked AI training crawlers and the biggest SEO
suites, but newer AI/answer-engine crawlers and unbounded site-audit tools
still crawled every public page. `/search` result pages were also crawlable
despite being marked private for caching, and tracking parameters created
endless duplicate URLs.

### Completed
- `lib/seo/robotsPolicy.ts`: added 19 more blocked user agents — AI/answer
  engines (`OAI-SearchBot`, `AI2Bot`, `Ai2Bot-Dolma`, `ImagesiftBot`,
  `img2dataset`, `PanguBot`, `Timpibot`, `VelenPublicWebCrawler`,
  `Webzio-Extended`, `YouBot`, `iaskspider`, `FriendlyCrawler`,
  `cohere-training-data-crawler`) and site-audit/link crawlers
  (`Screaming Frog SEO Spider`, `SeekportBot`, `linkfluence`,
  `netEstate NE Crawler`, `SiteAuditBot`, `Xenu Link Sleuth`).
- `/search` added to `PRIVATE_PATHS`, so query-space result pages stay out of
  the index and out of the crawl budget.
- New `DISALLOWED_QUERY_PATTERNS` (`utm_*`, `fbclid`, `gclid`, `gbraid`,
  `wbraid`, `msclkid`, `ref`) are merged into the wildcard `disallow` list.
- `scripts/test-robots.mjs`: asserts the new blocked agents, `/search`, and the
  tracking-parameter patterns.

### Verification
- `npm run test:robots`: passes.
- `npx tsc --noEmit`: passes.
- Targeted ESLint on changed files: passes.

### Notes
- robots.txt is advisory; Cloudflare WAF (see
  `docs/CLOUDFLARE_TURNSTILE_SETUP.md` §4.6) remains the enforcement point.
  `BLOCKED_BOTS` is the canonical list to mirror there.
- No production build, deploy, or Cloudflare rule was added.

## 2026-11-02 — Homepage image pool trimmed + hard asset caching

### Context
A homepage request audit (fetch HTML, follow every referenced asset, charge its
bytes) showed the images were small (10 requests / 92 KB, all ImageKit
transforms working), but the homepage still asked for ten random artists while
rendering at most six cards + one hero card, and the mouse-trail pool drew from
all ten. `public/` images were also only cached for 7 days.

### Completed
- `lib/services/homeDataService.ts`: `HOME_ARTIST_COUNT = 5`, cache key bumped
  `:v2` -> `:v3` so cached 10-artist payloads are not reused. The hero card,
  bento grid and mouse-trail pool all derive from this one array, so the
  homepage now requests at most 5 artist images.
- `netlify.toml`: `public/` images (webp, png, jpg, jpeg, svg, ico, avif) moved
  from 7-day to `public, max-age=31536000, immutable`.
- `next.config.ts`: the Next static-asset rule now also covers `avif`, `gif`,
  `mp4`, `webm`, `ttf` and `otf` at 1 year immutable.

### Verification
- `npx tsc --noEmit`, targeted ESLint: pass.
- Dev smoke: `/api/home-data/artists` returns 5 artists; `/eye.webp` carries
  `public, max-age=31536000, immutable`.

### Notes
- ImageKit URLs are third-party: their `Cache-Control` comes from ImageKit, not
  this repo. Set a long browser TTL in the ImageKit dashboard to get the same
  effect, and prefer new filenames over overwriting an image that is already
  cached (an immutable 1-year URL cannot be invalidated).
- `netlify.toml` headers only apply on Netlify, so they cannot be verified from
  the local dev server.

## 2026-11-02 — Duplicate favicon download removed

### Context
The homepage request audit showed 10 image requests / 92 KB, of which **63 KB
were icons**, and `/favicon.ico` was downloaded twice per first visit
(`/favicon.ico` and `/favicon.ico?favicon.<hash>.ico`). Cause: the file
conventions in `app/` (`favicon.ico`, `icon.png`, `apple-icon.png`) emitted one
set of `<link>` tags while the explicit `icons` metadata in `app/layout.tsx`
emitted another.

### Completed
- Deleted `app/favicon.ico`, `app/icon.png`, `app/apple-icon.png`. Icons stay in
  `public/` and are declared once, in `app/layout.tsx` metadata.
- Dropped `icons.shortcut` so browsers use the declared PNG icons instead of
  probing `/favicon.ico`. The file remains in `public/` for crawlers and older
  clients (still 200).
- `scripts/optimize-favicons.mjs` no longer writes or copies icons into `app/`,
  so regenerating favicons cannot reintroduce the duplicate layer.

### Verification
- `npx tsc --noEmit` and targeted ESLint on `app/layout.tsx` and the script: pass.
- Dev: 3 declared icon links (`favicon-48x48.png`, `favicon-96x96.png`,
  `apple-touch-icon.png`), 28.1 KB if every one is fetched, vs 63.0 KB before and
  no second `/favicon.ico` request. Desktop Chrome fetches only the two PNGs
  (~9.6 KB); `apple-touch-icon` is an iOS-only request.
- `/favicon.ico`, `/icon.png` (used as `siteConfig.ogImage`) and
  `/apple-touch-icon.png` all still return 200.

## 2026-11-02 — Crawler allowlist gate (origin)

### Context
A blocklist is always one bot behind. The requirement is "Google, Bing and
ChatGPT, plus link previews — nothing else", which robots.txt cannot express.

### Completed
- `lib/seo/botPolicy.ts`: `isBlockedCrawler(ua)` — explicit denials first, then
  the `ALLOWED_BOTS` + uptime-monitor allowlist, then a crawler-shaped product
  token test (`SomethingBot/1.0`, `*-crawler/2`, `*spider/3`). Unknown future
  bots are rejected without a list update. Phone model names (`CUBOT X19`) and
  browser engines (`AppleWebKit/537.36`) are explicitly not matched.
- `proxy.ts`: blocked crawlers get a 403 with `private, no-store`,
  `Vary: User-Agent`, `X-Robots-Tag: noindex` before any redirect/render work.
  Applied only to the already-matched paths (city, category, artists, blog,
  events) so no new edge invocations are introduced.
- ChatGPT: `ChatGPT-User` and `OAI-SearchBot` moved from `BLOCKED_BOTS` to
  `ALLOWED_BOTS` (citations/referrals). `GPTBot` training crawl stays blocked.
- `scripts/test-bots.mjs`; `npm run test:bots` added to the `test` chain.
- `docs/CLOUDFLARE_TURNSTILE_SETUP.md` §4.6b: Cloudflare-maintained
  "Block AI bots" toggle, optional crawler-shape WAF rule, and the warning not
  to block social preview fetchers.

### Verification
- `npm run test:bots`, `npm run test:robots`, `npx tsc --noEmit`, targeted
  ESLint: pass.

### Notes
- Dev smoke showed the 403 inheriting `Netlify-CDN-Cache-Control: public,
  s-maxage=3600` from `next.config.ts` (CDN headers beat `Cache-Control`), which
  would let an edge cache one bot's 403 and serve it to visitors. The 403 now
  sets `no-store` on both CDN headers explicitly.
- A user-agent allowlist stops polite-but-uninvited crawlers, not attackers who
  spoof Googlebot. Cloudflare Bot Fight Mode plus the free rate limit rule are
  the controls for those; full coverage cannot live in middleware without
  paying an edge invocation per request.
- Paginated/plain `/artists`, `/` and `/sitemap*` are outside the proxy matcher
  and therefore covered only by robots.txt and Cloudflare.

## 2026-11-13 — Netlify compute reduction

### Context
Production observations showed ~33k requests/day, 29.3k hitting the Next.js
Server Handler, and `Cache-Control: public, max-age=0` with repeated
`cache-status: fwd=stale; fwd-status=304`. Public pages were capped at
`s-maxage=3600` by `next.config.ts`, so Netlify Edge revalidated and invoked the
function indefinitely. Homepage widgets also fetched `/api/events` and
`/api/reviews` from the browser.

### Completed
- `next.config.ts` / `lib/cache/publicRoutes.ts`: removed the blanket shared
  HTML/API cache headers. Next/Netlify now emits per-route TTLs (static 1y, ISR
  revalidate, durable edge cache) instead of a fixed 1h cap.
- ISR: static pages `revalidate = false`; artist profiles 7d; listings/city/
  category/events 6h; blog 1d; about/categories 1d; home 1d.
- `lib/cache/revalidate.ts`: Next 16 `revalidateTag(tag, "max")` + targeted
  `revalidatePath()` on artist/blog/event/review admin writes.
- Homepage: events and reviews are fetched server-side and passed into
  `HeroSection` / `TestimonialsMarquee`; both client fetches were removed.
- `AuthProvider`: remembers anonymous/logged-in state in a non-HttpOnly hint
  cookie, so repeat anonymous visits do not call `/api/auth/session`.
- Disabled `Link` prefetching on remaining public content links.
- `lib/services/*`: `unstable_cache` for distinct categories/cities, category
  counts, blog/event categories, and homepage reviews; tags invalidate on admin
  writes.
- `public/.well-known/traffic-advice` + `netlify.toml` header: opts out of the
  Chrome prefetch proxy.

### Verification
- `npm test`: 38 tests pass.
- `npx tsc --noEmit`: passes.
- Targeted ESLint on changed files reports only pre-existing `any` /
  unescaped-entity errors; repo-wide `npm run lint` still has 337 pre-existing
  errors.
- No production build, deploy, or Cloudflare rule was applied.

### Notes
- Owner action: deploy once, then add Cloudflare Cache Rules (public HTML 15m,
  bypass RSC/auth/admin/API, cache public APIs/sitemaps) and Bot Fight Mode +
  the rate limit rule. Cloudflare is the enforcement point for the bot traffic.
